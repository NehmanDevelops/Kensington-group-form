Power Automate How-To

Kensington group & traveller automations — how to check them, and what to do when one breaks. Red circles and numbers in the screenshots show where to click.

Before you start: the sign-in for the shared Power Automate account (service.corp.groups@kensingtoncorporate.com) is stored in Sabre — it is not written on this page. Don’t edit or delete a flow unless a step below tells you to. Looking around is always safe.

1Sign in

  1. Go to make.powerautomate.com and sign in with the shared account (details in Sabre).
  2. Check the top bar says Environments → TravelEdge (default). All of our flows live in that environment. If it shows another environment, click it and switch.

1Find a flow  →  2Open it

🎬 Watch: finding and opening a flow

In the left menu click My flows, then open the Shared with me tab (circle 1). Every flow Nehman owns is shared with the shared account, so they all appear here (16 at the time of writing).

Scroll the list and click the flow’s name (circle 2). Tip: on the list, a greyed-out icon with a small “no entry” sign means the flow is switched off.

3Is the flow turned on?

🎬 Watch: checking Status and the run history

The flow’s page shows Status (circle 3) — it should say On. Below it is the 28-day run history (circle 4): every time the flow ran, with a green Succeeded or red Failed. All runs (circle 5) opens the full list.

If it says Off: use Turn on in the top toolbar, then check a few minutes later that it ran.
Also on this page: Connections (top right) shows whose account the flow uses to read mail / write to sheets. Co-owner shows who can edit it (NR = Nehman, SG = the shared account).

4Did it actually run? (“click here to see if it ran”)

🎬 Watch: opening a run to see the green ticks

In the run history, click the most recent date. A green bar says “Your flow ran successfully” (circle 1) and every step shows a green tick (circle 2). Resubmit (circle 3) re-runs that same email/event again.

Harmless warning: you may see a red banner “There’s a problem that needs to be fixed to trigger this flow”. If the detail says “It hasn’t been triggered successfully in the last 28 days” (circle 2 below), nothing is broken — no new email or row has arrived for it lately. This is normal for the Canada parser. It only matters if emails did arrive and nothing ran.

5Find and re-run failed runs

🎬 Watch: filtering to Failed runs (none showing means no failures)

  1. On the flow’s page click All runs.
  2. Top right, click the All runs filter (circle 1) and choose Failed runs (circle 2).
  3. Click a failed run. The step with a red cross is what broke — click it to see the error message.
  4. Fix the cause if you can (see Common fixes), then click Resubmit at the top of that run. For the CVENT parsers it is safe to resubmit: the parser skips people it has already saved, so nobody is doubled up.
After a long outage (e.g. the parser was down), resubmit every failed run since it stopped, then check the traveller sheet to make sure the people appear.

Common problems and fixes

What you seeWhat to do
Status says OffOpen the flow → Turn on. (Smartsheet or Outlook triggers sometimes get switched off after repeated failures.)
A run Failed at the first step (mailbox / Smartsheet trigger or action)Usually the connection expired. On the flow page, under Connections, click the warning/Fix link and sign in again. If it is the owner’s connection, Nehman (or the new owner) must do it.
A run Failed at the HTTP stepOur website/parser returned an error. Open the run → HTTP step → read the response. Try Resubmit once; if it fails again the code needs fixing (use the portals).
Emails arrive but no run appearsThe flow is off, or can’t read the mailbox. Confirm the shared account can open the shared mailbox (Canada / USA) in Outlook; if not, ask IT for Full Access to that mailbox.
“Premium”/licence errorFlows using the HTTP step need a Premium licence on the flow owner. Ask IT to assign/renew it before removing it from anyone.
Everything fails at onceCheck whether the Smartsheet API token was regenerated (the website needs it updated in Vercel), and whether the owner’s password was changed (connections then need re-signing-in).

Handover risks (read once)

  • Flows run on the original owner’s connections. The flows are co-owned by the shared account, but connections such as Office 365 Outlook were created with Nehman’s sign-in (visible in the Connections box). If Nehman’s account is disabled, those flows will fail until someone re-signs the connections with an account that will stay.
  • Never “export and import” a flow to move it — web-triggered flows get a new address and the forms break.
  • Premium licence sits with the owner. Move it deliberately (add first, remove after).
  • When in doubt, ask before editing. Every flow can be turned off/on safely; deleting is not reversible.
